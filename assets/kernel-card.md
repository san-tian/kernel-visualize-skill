# Kernel 卡模板

外卡收拢标题所指调用的所有信息。沿 **Input → 执行 → Output** 阅读，Input 和 Output 给出源、目标和交接，中间标出这次调用如何执行。若能在所选源码分支或 trace 定位到一次 launch，用实线发射框。再次展示同一核的后半段，用虚线续段，给出原核名与新增 0 次发射。遇到组合流程、条件派发、由后端选择的操作或视图，用中性的实现范围标出已知边界。

| 标题中的类型 | 何时使用 | CTA 栏的起点 |
| --- | --- | --- |
| 显式 GPU kernel · `kernel` | 能在所选路径定位到一次 Triton `fn[grid](...)` 或 CUDA launch。 | 给出该次发射的 grid。若分两处讲同一次发射，后一处注明「沿用上一步，新增 0 次」。 |
| PyTorch 算子 · `torch` | 展示的是 `torch.mm`、`Tensor.to`、`repeat_interleave`、`mul_` 等框架接口。 | 写出实际 dtype、设备、分支。可从后端源码或 trace 确认的发射才计数。 |
| 后端库调用 · `library` | 该格定位到具体库的入口，例如 cuBLAS GEMM。 | 说明算法与 grid 由哪个后端决定，记录已核实的配置或测量值。 |
| 张量视图 · `view` | 已确认本例的切片、转置等只改变地址、形状或步幅，继续共享原存储。 | 创建该视图本身 0 次设备发射、0 B 数据搬运。会物化输出的分支单列。 |
| 数据复制 · `copy` | 展示主机与设备之间或两个设备缓冲之间的一次具体复制。 | 标出源、目的、字节数和机制。已确认由复制引擎执行时，CTA 不适用。 |
| 组合流程 · `composite` | 一个 helper 编排多次子调用，或一格串联多个计算步骤。 | 列子调用和条件，已知的子 launch 分别记账；父级不重复计数。 |
| 集合通信 · `collective` | 展示某个并行组上的 all-gather、all-reduce 等通信原语。 | 写调用者与通信后端，数据按每 rank 的发送和接收统计。实际设备 grid 需核实实现。 |
| 教学示意 · `example` | 为解释数学、分块或数据流而给的假设程序。 | 明确哪些数量由假定的 grid 推导，运行记录另列。 |

伪代码保留作者写下的换行和缩进。长行在代码块内横向滚动，键盘焦点清晰可见，桌面对照的左右两列保持对齐。支持 JavaScript 时，仅对溢出的代码块提供「放大代码」，用页面可用宽度展示同一段代码。关闭或按 Esc 后焦点回到原按钮。关闭 JavaScript 仍能在原代码块横向读到行末。采用标准调用卡的网页可随页面加载一次[宽栏样式](kernel-code-reader.css)和[阅读脚本](kernel-code-reader.js)。离线导出会自动内嵌这两个文件。

Input 和 Output 以张量的物理意义命名。伪代码中的下标和维度在展开的变量表各解释一次。相互依赖的下标可放同一行。若激活或权重的数值未采样，给出来源和能确定的切片。库入口的伪代码可写实际调用和返回，CTA 栏写由哪个后端选择 grid、还缺哪段记录。数字第一次出现时标明取自本批输入、模型形状、启动配置、分块规则或实测。

**例子 · `assign_extend_cache_locs_uniform` 的地址表。** 本批选择 4 个请求，本次启动固定每请求 6 个验证位置。本路径有一次已定位的 Triton 发射，grid 为 (4,)，每个 CTA 负责一个请求。

| 卡内字段 | 本例 |
| --- | --- |
| Input · 源 | 先读本卡的 4 个请求池行号和 4 个前缀长度；本例二者均为 int64，各 32 B。每个请求在对应的请求到 token 映射行，从前缀末端开始读 6 个 int32 槽位号，4×6×4 B = 96 B。若在同一核准备锚点词，再读 4 个词号共 32 B。启用页翻译时，每张页表每个命中项另读 8 B。 |
| 中间 · 一次发射 | 每个 CTA 从请求到 token 映射行加载本请求的 6 个槽位，在核内把这 6 个值存入输出地址表。可选页翻译还会访问全局页表。 |
| Output · 目标 | 在本卡写 `out_cache_loc[请求, 验证位置]`（按行看），每个 int64 数字表示该位置使用哪个虚拟 KV 缓存槽。4×6×8 B = 192 B，K/V 向量写入量为 0 B。本例的锚点准备分支还写 24 个 int64 序列位置共 192 B，以及每请求 1 个锚点词号共 32 B。完整注意力池与滑窗池各自启用的物理槽编号表均为 int64[24]，每表 192 B。 |
| Output · 读者、交接和通信 | 目标验证使用每请求全部 6 个槽位。草稿批次取每行前 5 项，行间跳过 1 项。为槽编号表、位置表分别整理成连续数组时，每张表都需读、写各 4×5×8 B = 160 B。实际 K/V 缓存的内容在这一步搬运 0 B。在同一张卡执行，跨卡 0 B。 |

上表按源码形状计算本卡逻辑量。缓存带来的实际 HBM 流量需要硬件计数器。

## 怎样区分发射、显存访问和片上计算

一次 kernel 从发射到完成，可以多次读写全局内存。例如同一 CTA 循环遍历特征块，每轮加载一个输入 tile、累加局部结果，最后才写入结果张量。图中的 Input 和 Output 描述被访问的存储，加载和存储指令都在执行框所示的程序中发生。两张卡首尾相接时，先定位两块存储的地址与生产、消费指令，再判断是否有额外复制。

- **每个线程的寄存器**可以存放该线程的局部值。每线程寄存器用量和 spill 可核对编译报告，实际发生的 spill 读写量可查设备计数器。
- **同一 CTA 的共享内存**可以供多个线程交换 tile。一个线程读取其他线程写入的数据时，按依赖使用适当范围的同步，例如 CTA 级屏障。只有确认使用共享内存时才标出它。
- **全局内存读写**是 kernel 指令访问的逻辑地址。交接时两个核可以使用同一个地址。kernel 的结束或启动本身不会复制该缓冲，也不要求将缓存全部刷回 HBM。L1/L2 命中、存储行为与访存合并都会影响硬件流量；用计数器核实。

## 填写卡内的交接与传输

先查张量的创建、切片和实际写入位置，再跟踪下一位使用者。例如库调用直接接前一步的输出地址，应在箭头写“复用地址，新增复制 0 B”。下游读数据的字节归下游。若两个独立地址之间有 `copy_`，写清在哪一次调用中复制，源读与目标写分别是多少。分配或取得预留缓冲后，找到首次真正初始化或写入的调用再记写入量。

对计算产生的临时结果，写明该中间量是在本卡全局内存建表供另一核读取、在原地址改值，还是在同一融合核里继续使用。只能确认 CTA 内使用时，就标到 CTA。源码若显式使用共享内存，可标出其缓冲与范围。要确认编译后的寄存器分配、溢出或实际访存指令，再核对编译产物。融合前后沿同一张量画图，把消失的写回和后续读回分开列出。源码只给形状时写清是张量覆盖字节，若按 CTA 或多次调用累计则单列。库内部工作区、每卡远端路由数等缺参可给公式或未知原因。需要物理 HBM 流量时，核对缓存和内存计数器。需要耗时时，查本次设备时间线，并考虑计算与通信重叠。

对于 `all_gather`，可用组大小 P、各卡等长本地切片 L 作例子。每卡贡献 L 字节并接收其他卡的 (P−1)×L 字节，完整输出为 P×L 字节。将并行组、dtype、切片行或列代入本例。组内转发、协议开销和拓扑会影响链路实测值。遇到 all-reduce 或按专家路由，改按该调用的规约或路由计数推导。

例如 `wo_b` 的 `index_select` 按 24 个 token 行的槽号从常驻权重表选 A，Output 写出独立的 BF16[24,32,8192] 逐行权重，共 12 MiB。其 Output 的下一读方为收缩的 `torch.bmm`，交接传转置视图，新增复制 0 B。收缩调用的 Input 再说明如何读取这些权重。阶段内需要说明多条路径的汇合关系时，可以在附图只追踪选中的输出；每张调用卡仍完整保留自己的 Input / Output。

## 用同一模板生成 HTML

下面是一份可在仓库根目录运行的填写示例。假设一个教学 kernel 把同一特征偏置加到每个 token 的隐藏状态，写给下一层。沿着尾块 `(1,1)` 追踪最后一个特征。网页使用同一个渲染函数与样式。[HTML 渲染函数](../scripts/kernel_card.py) · [卡片样式](kernel-card.css) · [数据流样式](kernel-memory-route.css)

```python
from scripts.kernel_card import render_call_template, render_card_body

add_bias = dict(
    kind=("example", "按下方教学伪代码假设一次发射。CTA 数由示例形状推导。"),
    execution=(
        "add_bias[grid](X, bias, Y, T, D)（教学伪代码）",
        "假设由一个 Triton 程序在 GPU 上执行。",
        "每个程序按行、按列块执行带掩码的加法。",
        "该教学模型假设一次 add_bias 发射，文中的分块数由示例 grid 推导。",
    ),
    inputs=[
        ("X · 上游线性层输出的隐藏状态", "BF16，X[1,4:5] 共 2 B。", "选尾块跟踪第二个 token 的最后一个特征。"),
        ("bias · 本层每个特征共享的偏置", "BF16，bias[4:5] 共 2 B。", "偏置只由特征列决定，两行使用同一张表。"),
        ("T、D · 位置数和每个位置的特征数", "T=2，D=5。", "教学例选两个位置、五列，便于手算尾块。"),
        ("t、g、J · 行号、列块号、块内列号", "t=1，g=1，J=4…7，仅列 4 有效。", "演示第二行的第二块，每块 4 列，写入需满足 J<D。"),
    ],
    program="""t, g = program_id(0), program_id(1)
J = 4*g + arange(4)
valid = J < D
x = load(X[t,J], mask=valid)
b = load(bias[J], mask=valid)
store(Y[t,J], bf16(fp32(x) + fp32(b)), mask=valid)""",
    grid="grid=(T, ceil(D/4))=(2,2)，共 4 个 CTA。每行各有一个满块与一个尾块。4 个块都有有效列。",
    paired_route=True,
)
io = (
    "本卡上游隐藏状态 X[0:2,0:5] 共 20 B；偏置 bias[0:5] 覆盖 10 B，两行各读一次共 20 B。",
    "本卡独立输出 Y[0:2,0:5]，写 20 B。",
    "下一层逐元素算子从 Y 的同一地址读 20 B。",
    "传 Y 的地址，新增复制 0 B。",
    "单卡计算，跨卡 0 B。",
    "尾块在块内相加，具体寄存器和共享内存布局未指定。",
)
print(render_call_template(
    "add_bias", add_bias["kind"][0], io, render_card_body(**add_bias),
    launch_scope="opaque", work="在教学伪代码中，尾块只对有效列 4 做加法。",
    boundary_note="这里演算假设的分工，缺少实际发射记录。",
    link_kind="local", evidence="教学假设 · 单卡一次调用的逻辑量，未做硬件测量。",
))
```

`io` 六项依次填读取、写入、下一读方、交接、传输和片上暂存。读写和传输归该调用的 Input / Output，片上暂存归中间的执行区。用 `evidence` 指定计数范围和证据来源。

`launch_scope` 选择执行区的含义。已确认的一次发射填 `single`，同一次发射的后段填 `continuation`，并在 `boundary_note` 点明前段和新增发射数。多次执行填 `multiple`，随运行分支变化填 `conditional`，只确认到框架或库入口填 `opaque`，单纯张量视图填 `view`，主机代码填 `host`。一个 `torch.*` 调用的设备端发射数以所选分支和可核实的设备记录为准。若要把已知底层 kernel 展开，可另画子卡，发射数只在该核计一次。

`link_kind` 选择图上的通信标签。本卡处理填 `local`，主机与 GPU 之间填 `host`，已定位的跨卡收发调用填 `peer`。需要特定分支才跨卡时填 `conditional`，证据不足时填 `unknown`。借助 `link_side="input"` 或 `"output"` 把通信归给相应方向。本例模板默认把主机传入的 `host` 归 Input，其余归 Output。双向调用可用 `input_link` 单写路由到专家的输入传输，用 `io[4]` 写计算后返回的激活，两边分别给端点、条件与载荷。

本例的 Input / Output 写整次调用覆盖哪些地址、读写多少和交给谁。展开后用尾块的 `J<D` 解释地址 `Y[1,4]` 为什么能写。[Decode 对照案例](../examples/decode-comparison/README.md)
