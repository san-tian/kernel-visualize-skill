# Kernel 卡模板

先选定图上这一行要展示的调用边界，然后填写五栏。折叠标题直接给出调用名及类型，在 CTA 栏写明当前分支可证实的发射次数。多个源码调用可以合成一段教学流程；分组标题给出清单单位，例如「5 个源码调用」，并画出它们之间的数据依赖。

| 标题中的类型 | 何时使用 | CTA 栏的起点 |
| --- | --- | --- |
| 显式 GPU kernel · `kernel` | 能在所选路径定位到一次 Triton `fn[grid](...)` 或 CUDA launch。 | 给出该次发射的 grid。若分两处讲同一次发射，后一处注明「沿用上一步，新增 0 次」。 |
| PyTorch 算子 · `torch` | 展示的是 `torch.mm`、`Tensor.to`、`repeat_interleave`、`mul_` 等框架接口。 | 写出实际 dtype、设备、分支。可从后端源码或 trace 确认的发射才计数。 |
| 后端库调用 · `library` | 该格定位到具体库的入口，例如 cuBLAS GEMM。 | 说明算法与 grid 由哪个后端决定，记录已核实的配置或测量值。 |
| 张量视图 · `view` | 已确认本例的切片、转置等只改变地址、形状或步幅，继续共享原存储。 | 创建该视图本身 0 次设备发射、0 B 数据搬运。会物化输出的分支单列。 |
| 数据复制 · `copy` | 展示主机与设备之间或两个设备缓冲之间的一次具体复制。 | 标出源、目的、字节数和机制。已确认由复制引擎执行时，CTA 不适用。 |
| 组合流程 · `composite` | 一个 helper 编排多次子调用，或一格串联多个计算步骤。 | 列子调用和条件，已知的子 launch 分别记账；父级不重复计数。 |
| 集合通信 · `collective` | 展示某个并行组上的 all-gather、all-reduce 等通信原语。 | 写调用者与通信后端，数据按每 rank 的发送和接收统计。实际设备 grid 需核实实现。 |
| 教学示意 · `example` | 为解释数学、分块或数据流而给的假设程序。 | 明确哪些数量由假定的 grid 推导，运行记录另列。 |

例如图上若写 `torch.mm`，标 PyTorch 算子。若已追到底层 GEMM 库，可把库画在它下面并用边连接上下层，发射只记一次。视图和复制也应按本例的分支判定。输入已在目标设备且 dtype 相同的默认 `Tensor.to` 可以直接返回原张量，而布尔掩码转 BF16 需要存储转换后的值。

````markdown
### `{调用名}` · {调用类型} · {这一步完成的动作}

{上游} → **{本层或模块的算子}** → {下游}。{这一次调用的配置、分支或算例条件}

**Input · 读哪些张量**

| 变量是什么 | 本例取值或切片 | 为什么取这个值 |
| --- | --- | --- |
| `{变量名}` · {所属模块、张量或下标的物理意义} | {具体值，或注明 dtype、大小的切片} | {请求位置、路由结果、模型形状、启动参数、核分块或示例选取} |

**伪代码**

**实现后端**　{从标题中的调用入口追到的库、函数或设备 kernel}。{说明该实现怎样完成这一步。若有多个实现，标出本例命中的条件；只能确认到框架入口时，写出确认更深一层所需的分派记录或 trace。}

```text
{用实际 block ID 定位输出坐标，或写出库、主机的真实调用边界}
{按 Input 的名字取值，写出影响结果的掩码、循环、精度和计算}
{写回 Output 的切片，或标出提前返回、视图复用、通信的位置}
```

**Output · 写到哪里**

| 本卡输出与去向 | 本执行单元的写入 | 大小 |
| --- | --- | --- |
| `{张量名}`，{dtype 和本卡形状}，由 {下游} 读取 | `{张量名[下标或半开区间]}`，{新缓冲、原址、视图或跨卡目的地} | {本片字节数，单卡本次合计或计算式} |

**CTA · 发射与线程块分工**

{先说明此条目能确认的发射边界及依据。} {已知一次发射的 grid 时，代入各轴公式和本例数值，给出单卡 CTA 数与一个代表块的输入、输出切片。} {后端不透明时写决定分块的后端和缺少的证据；视图则直接说明共享存储。}

**显存与跨卡通信**

{本卡读、写哪些切片，中间值留在哪里。} {有跨卡通信时给出并行组、发送和接收的切片、每卡有效字节。纯本卡计算可写“跨卡 0 B”。}

[调用与发射处]({固定版本链接}) · [kernel 定义]({固定版本链接})
````

Input 每个符号解释一次，包括下标和形状字母。相互依赖的下标可在一行一起解释。激活、权重或路由结果的数值未采集时，给出实际的来源和可以确定的切片。整次调用的字节数较多时，在变量表下按需展开。原地累加时把同一地址列在两端。视图标明共享的原存储和新增写入 0 B。对后端库入口，伪代码可以展示调用和返回，CTA 栏注明决定 grid 的后端以及待核实的条件。主机调用列出它实际触发的复制或子调用。数字随批变化、由模型形状决定、由启动配置固定、由核分块规定或来自实测时，在首次使用处标清。

## 用同一模板生成 HTML

下面是一份可在仓库根目录运行的填写示例。假设一个教学 kernel 把同一特征偏置加到每个 token 的隐藏状态，写给下一层。沿着尾块 `(1,1)` 追踪最后一个特征。网页使用同一个渲染函数与样式。[HTML 渲染函数](../scripts/kernel_card.py) · [卡片样式](kernel-card.css)

```python
from scripts.kernel_card import kind_badge, render_card_body

add_bias = dict(
    kind=("example", "按下方教学伪代码假设一次发射。CTA 数由示例形状推导。"),
    backend=("Triton 风格教学示意", "假设每个程序处理一行中的四个特征，按列读取偏置并把有效列写回。"),
    inputs=[
        ("X · 上游线性层输出的隐藏状态", "BF16，X[1,4:5] 共 2 B。", "选尾块跟踪第二个 token 的最后一个特征。"),
        ("bias · 本层每个特征共享的偏置", "BF16，bias[4:5] 共 2 B。", "偏置只由特征列决定，两行使用同一张表。"),
        ("T、D · 位置数和每个位置的特征数", "T=2，D=5。", "教学例选两个位置、五列，便于手算尾块。"),
        ("t、g、J · 行号、列块号、块内列号", "t=1，g=1，J=4…7，仅列 4 有效。", "演示第二行的第二块，每块 4 列，写入需满足 J<D。"),
    ],
    program="""t, g = program_id(0), program_id(1)
J = 4*g + arange(4)
valid = J < D
x = load(X[t,J], mask=valid)
b = load(bias[J], mask=valid)
store(Y[t,J], bf16(fp32(x) + fp32(b)), mask=valid)""",
    outputs="Y[t,J] · 新分配的 BF16 输出，形状 [T,D]，供下一层读取",
    output_note="J 中小于 D 的元素是有效特征列。块 (1,1) 只写 Y[1,4:5]。",
    output_size="尾块写 2 B，本次单卡共写 2×5×2 = 20 B。",
    grid="grid=(T, ceil(D/4))=(2,2)，共 4 个 CTA。每行各有一个满块与一个尾块。4 个块都有有效列。",
    traffic="按有效元素算，本卡逻辑上读 X 20 B、bias 20 B，写 Y 20 B。两行复用相同的 10 B 偏置，物理 HBM 读量取决于缓存。跨卡 0 B。",
)
print(
    '<details><summary><code>add_bias</code> ' + kind_badge(add_bias["kind"][0])
    + "</summary>" + render_card_body(**add_bias) + "</details>"
)
```

将这个可展开条目放到流程图对应的位置，在页面引入 `kernel-card.css`。实际的 Q/KV 收缩算例可以看到同一张卡怎样描述多输入、低秩输出和两条执行分支。[Decode 对照案例](../examples/decode-comparison/README.md)
