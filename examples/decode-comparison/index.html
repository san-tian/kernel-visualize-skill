输入请求甲上次生成的词是「我」。

从「我」出发，草稿模型依次猜出「想、喝、茶、再、走」。目标模型把锚点和这五个候选排成六行。

DSpark 用 SGLang 的 CUDA 核写缓存，用 Triton 核选候选词 草稿层调用 fused_k_norm_rope_flashmla 写入 KV。得到词分数后，每个草稿位置由 _markov_sample_partial_kernel 先选块内候选，再由 _markov_sample_finish_kernel 选出一个词。

怎样从调用的 Input 和 Output 判断有没有额外复制？

寄存器保存每个线程自己的临时值。同一线程块的线程可借助共享内存交换数据，协作读写时按依赖同步。框内的 load 和 store 仍可访问全局显存。具体用到多少寄存器、共享内存，或有无溢出，要检查编译结果。两个独立 kernel 常借助同一全局缓冲交接：前者写、后者读。交接地址本身不会再复制一份张量，读取也可能命中 L2。

调用 copy_、index_select，或把结果写到另一个地址指明源、目标和执行复制的调用。复制发生在那一步。下游拿到目标地址时，同一份复制只记一次。
用 add_ 原址改值，或在融合核内生成中间值原址加法需要读旧值、写新值。块内中间值就地用于下一项计算时，单列该临时张量省掉的显存写入和重读。
目的缓冲在另一张卡或主机标发送方、接收方、传哪个张量和字节数。复制可能发生在集合通信或计算核内部。相同数据在接收卡的写入与链路载荷只算一次传输。
