    计算原理与算例

    上一步已经选出「我」。引擎把它称为锚点。草稿模型拿到「我」和四个占位符，一次前向就给五个位置各算一组候选分数。接下来才从这些分数中选词。

    给新位置分配缓存地址assign_extend_cache_locs_uniform
    根据每条请求当前的长度，先算出这轮各位置可写入的 KV 缓存地址。KV 是注意力留下的键和值，已有上下文可以在下一轮继续读。
    算出五个位置的词分数DSparkV4CudaStage → compute_base_logits
    这里是模型调用，内部含多次 kernel 发射。本模型的三个草稿阶段用缓存读上下文、更新每行向量，最后把向量与各词的权重做点积，得到每个位置的基础分数。
    逐位置选出候选词_markov_sample_partial_kernel → _markov_sample_finish_kernel
    以贪心选词为例，先把前一个词带来的分数修正加到当前位置。各线程块分别找一段词表里的最高分，再从各段胜者中选出一个词。刚选的词又参与下一个位置的选择。

    请求甲得到草稿「想、喝、茶、再、走」。这些词都还要经过目标模型验证。

    DSparkV4CudaStage → compute_base_logits    		上一轮的 bonus token 成为锚点。草稿读锚点、占位输入、位置和已有草稿 KV，运行本模型配置的 3 个草稿 stage，经过 attention、专家层和输出投影，给出 5 个候选位置各自的词表分数。这是独立于目标模型的小模型前向。整组调用包含 GEMM、注意力、专家和归一化。各自的 grid 随草稿层形状、库选型和缓存长度确定；3 是 stage 个数。核对旧图中 CPU 等待时，要与 GPU 发射分别计数。

    计算原理与算例

    上一环节是专家的第一组投影（D1，gate/up），这里是第二组（D2，down）。专家的输入和激活都已经随请求改变，所以 down 的 LoRA 必须等激活算完。

    先算路由专家的增量_d2_shrink_per_token_kernel → bmm → sum
    路由侧每块管一行，循环这行选中的专家。它用各专家对应的 A2 压缩已带路由权重的激活，再把短向量相加。后面批量乘 B2、沿槽求和，得到路由增量。
    再算共享专家的增量共享侧 mm → 掩码 → bmm → sum
    共享激活先与拼在一起的所有槽的 A2 做矩阵乘，再用掩码只留下本行的槽，乘共享 B2，沿槽求和。这样会算出一批随后被清零的值。

    路由与共享两路各写了一张宽增量。最后一个 kernel 再把两张读回来，逐元素加到底模专家输出的对应位置。
